## Список требований, которым должны удовлетворить внешние интеграции

Интересный момент с распознаванием номеров и лиц.

Данные номеров и лиц по идее должны храниться в системах поставщиков поближе к устройствам тк шлагбаум и домофон должн работать при отсутствии Интернета.

Эти данные надо безопасно и легально передать поставщикам.

Если с номерами плюс-минус ясно, то с лицами всё хуже - ФЗ 572 прямо запрещает сбор биометрии в обход ЕБС. Будем считать, что мы работаем в юрисдикции, где сбор биометрии не запрещён.

### Требования к безопасности

Система не должна позволять операции с устройствами умного дома пользователям, которые не авторизованы это делать.

Должна быть возможность мгновенно заблокировать учётную запись конечного пользователя или отозвать доступ.

Передача персональных данных и данных биометрии во внешние системы должна соответствовать законодательству, а также учитывать критичность рисков, связанных с их утечкой..

Хранение персональных данных и данных биометрии должно соответствовать законодательству, а также учитывать критичность рисков, связанных с их утечкой.

### Протоколы аутентификации и авторизации

OIDC + OAuth с client credentials.

HTTPs / SSL обязательно.

IPs whitelist на стороне поставщика.

В контуре компании ограничить возможность делать запросы к внешнеим API только для определённых сервисов (чтобы, например, разработчик не смог открыть шлагбаум curl'ом)

### Взаимодействие между системами предприятия и внешней платформой

Основных сценариев два:

* Регистрация пользователя в системе поставщика (передача номера машины, фото лица) - это надо делать, если внешняя система подразумевает работу при отключенном Интернете
* Управление устройством (шлагбаумом, домофоном) из приложения

Оба сценария реализуются вызовами API поставщиков.
